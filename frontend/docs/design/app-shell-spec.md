# 앱 셸 (app-shell-spec)

> 화면이 「어디에」 놓이는지와 틀의 치수가 기준이다. 색·글자 값의 이름은 [app-ui-spec](app-ui-spec.md) 의 토큰을 쓴다.

## 1. 구조

```
┌────────────┬──────────────────────────────────────────────┐
│ 사이드바    │ 상단바 (비움 ············ 이름 · 역할 ▾)      │ ← 고정(sticky)
│ 222px 고정  ├──────────────────────────────────────────────┤
│ 브랜드      │ 본문                                          │
│ 메뉴 그룹   │   페이지 제목 · 설명                          │
│  메뉴       │   블록 …                                      │
│             │                                               │
└────────────┴──────────────────────────────────────────────┘
          모달(OverlayHost) · 토스트(Toaster)는 셸이 한 번만 그린다
```

- 구현: `src/app/shell/AppShell.tsx`(메뉴는 `SideNav.tsx`, 상단바는 `TopBar.tsx`), 스타일 `src/styles/app/shell.css`.
- 두 칸 격자다. 사이드바 222px, 본문은 나머지 폭을 모두 쓴다(최대 폭 제한 없음). 본문은 줄어들 수 있게 최소 폭 0.
- 대상 화면 폭은 데스크톱(1280px 이상)이다. 1250px·1150px 아래에서 일부 격자를 접는다(app-ui-spec 「간격·크기」).

## 2. 사이드바

화면 높이에 맞춰 고정되고(sticky, 높이 100vh) 메뉴만 안에서 스크롤된다. 흰 바탕, 오른쪽 1px 선(`line`).

| 영역      | 생김새                                                                                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 브랜드    | 안쪽 여백 위 18 · 좌우 18 · 아래 16px, 아래 1px 선. 마크(26px 정사각, 7px 라운드, 청록 바탕에 흰 글자 13px 굵게) + 간격 9px + 서비스명(15px 굵게, 자간 -0.2) 아래 부제(10.5px 회색, 500). 마크 · 서비스명 · 부제 값은 `src/app/brand.ts` 한 곳이다 |
| 메뉴      | 안쪽 여백 10px, 남는 높이를 채우고 넘치면 스크롤                                                                                                                                                                                                   |
| 그룹 이름 | 10px · 600 · `ink-faint` · 자간 0.6, 여백 위 16 · 좌우 10 · 아래 5px                                                                                                                                                                               |
| 메뉴 항목 | 13px · 600 · `ink`, 여백 8px 10px(그룹 아래 항목은 왼쪽 19px로 들여쓰기), 6px 라운드, 항목 사이 1px. 올리면 `surface-muted` 바탕. **현재 메뉴는 `brand-tint` 바탕 + 청록 글자 700**                                                                |

- 메뉴 항목에는 **아이콘을 두지 않는다**. 구분 없는 첫 메뉴(홈)는 들여쓰지 않는다(`app-nav__item--top`).
- 서비스명 · 부제 · 마크 · 로그인 화면 설명은 `src/app/brand.ts`, 브라우저 탭 제목은 `index.html` 의 `<title>` 이다. 새 프로젝트를 시작할 때 둘을 함께 바꾼다.
- 사이드바 하단에는 정보를 두지 않는다.
- 메뉴는 처음부터 모두 보인다(결정 0003). 화면이 없는 메뉴는 이름 오른쪽 끝(양 끝 맞춤)에 「준비 중」(`Tag` 회색)을 달고 흐리게 하지 않는다 —
  누르면 「준비 중」 화면(5절). 표시 글자는 링크 이름에 들어간다(화면 낭독기는 「설정 준비 중」으로 읽는다).

## 3. 상단바

본문 열 맨 위에 고정된다(sticky, 상단바가 본문보다 위에 겹침). 흰 바탕, 아래 1px 선, 여백 12px 24px, 요소 간격 14px.

- 왼쪽: 비운다. 오른쪽 버튼은 오른쪽 끝에 붙는다.
- 오른쪽: 작은 버튼 「이름 · 역할」(역할은 화면 이름 목록이 정해질 때까지 코드값 그대로) → 누르면 프로필 메뉴(팝오버, `ui/MenuButton`) →
  「로그아웃」 → 로그인 화면. 알림 · 「내 정보」가 필요하면 이 메뉴에 더한다.
- 수행 단위(버전 · 기간 등) 선택은 상단바에 두지 않는다 — 각 화면 안의 「맥락 띠」에 둔다(app-ui-spec 「컴포넌트」).
- 구현: `src/app/shell/TopBar.tsx` 를 `AppShell` 이 본문 열(`app-main`) 맨 위에 붙인다. `app-main` 은 여백 없는 열이고 본문 여백은 그 아래
  감싸개 `app-main__body` 가 갖는다 — 상단바가 열의 맨 위에 바로 놓여 스크롤해도 고정된다.

## 5. 메뉴와 라우팅

- 화면과 메뉴의 단일 출처는 `src/app/routing/pages-config.tsx` 다. 라우터와 사이드바가 이 목록을 읽는다.
- 메뉴 구분(`NavSection`)과 순서는 `NAV_SECTIONS` 와 이 목록의 순서다.
- 메뉴마다 공개 상태가 있다(결정 0003) — 「열림」(`status: "open"`)은 그 화면을, 「준비 중」(`status: "coming-soon"`)은 「준비 중」 화면
  (`src/app/pages/coming-soon/ComingSoonPage.tsx`)을 연다. 「준비 중」 화면은 제목(메뉴 이름) · 그 화면이 할 일 한 줄(`summary`) ·
  안내 상자 「준비 중인 화면입니다」이고, 예시 데이터는 보이지 않는다(기조 1). 진입은 다른 화면처럼 로그인만이다.
  기능이 완성되는 PR 이 그 메뉴를 「열림」으로 바꾼다.
- 화면 렌더 오류는 셸 안의 `RouteErrorBoundary` 가 받는다(사이드바는 남는다). 없는 주소는 NotFoundPage.
- 상세 화면처럼 메뉴에 없는 화면은 `nav: null`. 메뉴 강조는 그 화면이 속한 메뉴에 남긴다. 구분 없이 맨 위에 두는 메뉴(홈)는
  `nav: "구분 없음"`.
- 로그인(`/login`)·비밀번호 변경(`/password`)은 셸 밖이다 — `src/app/shell/StandaloneLayout.tsx`, 클래스 `app-standalone*`.
  바탕 가운데 폭 360px 한 줄에 브랜드(서비스명 21px 굵게, 가운데) → 20px → 카드(안쪽 여백 24px, 라운드 9px,
  테두리만 — 그림자 없음)를 놓는다. **로그인 화면만** 서비스명 아래에 서비스 설명 한 줄(12.5px 회색,
  `brand.ts` 의 `LOGIN_DESCRIPTION`)을 둔다 — 사이드바 부제와 별개의 로그인 전용 문구다. 비밀번호 변경 화면은 서비스명만 보인다. 로그인 카드는 **보이는 제목 없이** 폼만 둔다(브랜드와 「로그인」 버튼으로 무슨 화면인지 충분하다 —
  화면 낭독기용 제목만 숨겨 둔다). 비밀번호 변경 카드는 제목(15px 굵게)과 설명 한 줄(12.5px 회색) → 16px → 폼. 화면에 폼 하나뿐이라
  입력·버튼을 업무 화면보다 크게(10 × 12, 높이 약 38px) 두고, 버튼은 전체 폭에 앞 아이콘을 단다(처리 중에는 도는 아이콘).
  비밀번호 칸은 보기 버튼·Caps Lock 경고를 가진 `PasswordInput` 이다.
  오류는 두 화면이 같은 모양이다 — 칸의 문제는 그 칸 바로 아래, 어느 칸에도 속하지 않는 문제(로그인 실패·연결 실패)는
  주 버튼 바로 위에 빨간 글자 한 줄(`FormError`). 상자로 보이지 않는다. 비밀번호 변경 중 세션이 끝나면(관리자 초기화·회수) 로그인 화면으로 간다.
  로그인 화면의 「로그인」은 처리 중에만 끈다 — 빈 칸이어도 누를 수 있고, 누르면 칸의 실제 값을 읽어 빈 칸이면 그 칸 아래에 알린다(브라우저가
  채운 값을 첫 클릭에 보내기 위해). 비밀번호 변경 화면은 빈 칸이면 버튼을 끈다.
  나타날 때 아래에서 8px 올라오며 0.18초(토스트와 같은 움직임, 「동작 줄이기」면 바로 나타난다). 나머지 화면은 `src/app/routing/guards.tsx` 의
  `RequireLogin`(로그인 안 됨 → `/login`, 돌아올 경로를 location state 로) → `RequirePasswordChanged`(`mustChangePassword` → `/password`) →
  셸 순서로 감싼다. 세션이 중간에 끝나면(인증 요청 밖의 401) 전송 계층이 알려 같은 길로 로그인 화면에 간다.
- 로그인 뒤 갈 곳은 서버가 준 `defaultPage` 경로 그대로다(새 계정은 `/`). 등록되지 않은 경로를 다른 곳으로 대체하지 않는다 —
  없는 경로면 「페이지를 찾을 수 없습니다」가 보인다(기조 5).
- 홈 `/` 은 메뉴 「홈」이다(`src/app/pages/home/HomePage.tsx` — 서버 · 데이터베이스 · 파일 저장소 연결을 보이는 설치 점검 화면이자 조회 화면의
  참고 구현). 첫 기능을 만들면 그 프로젝트의 홈으로 바꾼다.
- 메뉴 강조는 `NavLink` 에 `end` 를 두지 않아 상세 경로(`/items/7`)에서도 상위 메뉴에 남는다. 홈 `/` 만 `end` 를 둔다 — 없으면
  모든 경로에서 홈이 강조된다(`src/app/shell/SideNav.tsx`).

## 6. 떠 있는 면

| 면          | 여는 법                                      | 닫는 법                                                              | 겹침 순서                |
| ----------- | -------------------------------------------- | -------------------------------------------------------------------- | ------------------------ |
| 모달        | `openModal({ title, size, render })`         | ✕ · Esc (바깥 클릭으로 닫지 않음. 겹치면 Esc 는 맨 위 모달만 닫는다) | 200                      |
| 토스트      | `toast(title, tone)` · mutation 실패 시 자동 | ✕ · 6초 후 자동                                                      | 300                      |
| 팝오버 메뉴 | 트리거 버튼 클릭 · ↓ · ↑                     | 항목 선택 · Esc · Tab · 바깥 클릭                                    | 30 — 트리거가 놓인 면 안 |

- 모달을 화면마다 따로 마운트하지 않는다. 스택은 `overlay-store` 하나가 소유한다.
- `size` 는 `"default"`(720px)·`"wide"`(980px) 중 하나를 반드시 고른다. 내용은 `ModalBody`(스크롤되는 본문)와
  `ModalFooter`(고정 바닥 — 왼쪽 안내 · 오른쪽 버튼)를 조합해 돌려준다. 바닥 버튼이 본문 입력 상태를 따르므로 둘을 한 컴포넌트가 소유한다.
- 팝오버 메뉴는 `overlay-store` 를 거치지 않는다 — 트리거 옆에 absolute 로 뜨고 상태는 부품 안에 있다(`ui/MenuButton`, 모양은 app-ui-spec 5절).
  상단바(z 20) 안에서는 상단바와 함께 겹치므로 모달·토스트 아래다. 모달 안에서 열리면 Esc 는 메뉴만 닫는다.
- 확인이 필요한 동작(삭제 등)은 브라우저 `confirm` 대신 확인 모달(`shared/ConfirmModal` 의 `openConfirmModal`)을 연다 — 문장 + 취소·확인
  (비가역 동작은 위험 버튼). 실행이 끝날 때까지 버튼을 잠그고, 실패하면 닫지 않고 사유(요청 ID 포함)를 보여 다시 시도하거나 취소하게 한다.
  연 팝업 위에 겹쳐 뜨므로 Esc 는 확인 모달만 닫는다. 지금 할 수 없는 삭제는 확인 대신 안내 모달(`openNoticeModal` — 문장 + 확인 하나)로
  이유와 대안을 보인다(design-concept 4절 「예외」).
- 겹침 순서: 상단바(본문 위, 그 안의 팝오버 메뉴 포함) < 모달 < 토스트.

### 토스트 치수

- 화면 오른쪽 아래(22px 띄움). `ink` 바탕에 흰 글자 12.5px · 600, 여백 11px 16px, 6px 라운드.
- 나타날 때 아래에서 8px 올라오며 0.18초 동안 나타난다. 「동작 줄이기」 설정이면 바로 나타난다.
- 성공·경고·실패 구분(tone)·사유·요청 ID 를 담는 동작은 저장소 규칙을 따른다. 초안은 한 가지 모양뿐이라 tone 은
  **왼쪽 3px 띠**로 구분한다 — 성공 청록 · 경고 호박 · 실패 적 · 안내는 띠 없음(app-ui-spec 8절 D6).
