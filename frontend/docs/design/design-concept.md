# 화면 원칙 (design-concept)

> 화면이 「왜」 그렇게 생겼는지의 기준이다. 구체 값(색 코드·px)은 [app-ui-spec](app-ui-spec.md), 틀과 치수는
> [app-shell-spec](app-shell-spec.md)이 정한다. 프로젝트의 사용자 · 핵심 동선이 정해지면 1절부터 채운다.

## 1. 누가 쓰나

프로젝트를 시작할 때 채운다 — 사용자(역할)마다 화면에서 하는 일을 한 줄씩 적는다. 역할 값 목록이 정해지기 전에는 화면에
코드값 그대로 보인다(루트 CLAUDE.md 「공통 어휘」).

- **(역할)**: (이 역할이 화면에서 하는 일)

## 2. 화면의 인상

- **업무 도구다.** 밝은 회청색 바탕 위에 흰 카드를 놓고, 주 색은 **청록 한 가지**만 쓴다. 나머지는 무채(남색 글자·회색)다.
- **밀도가 높다.** 본문 13px, 보조 글 11.5px, 표가 화면의 중심이다. 여백은 블록 사이 12~16px 로 촘촘하다.
- **장식이 없다.** 그라디언트·일러스트·이모지·장식용 그림자를 쓰지 않는다. 그림자는 떠 있는 면(모달 · 팝오버 메뉴)에만 있다.
- **상태가 어느 화면에서나 같은 이름·같은 색으로 보인다.** 값을 정할 수 없으면 그 사실을 보이고 값을 지어 채우지 않는다(루트 기조 1).
- **근거로 바로 간다.** 목록의 한 건에서 그 대상(상세 · 원본)으로 한 번에 이동한다. ID 자체가 이동 버튼이 된다.
- **메뉴는 일의 순서대로** 놓는다. 순서의 정본은 `src/app/routing/pages-config.tsx` 다.

## 3. 색을 쓰는 규칙

1. **색은 상태에만 쓴다.** 분류·속성(이름, 유형, 필수 여부 등)은 색 없는 글자로 둔다. 사용 여부는 동작에 드는지를
   바꾸는 상태라 태그로 보인다(사용 청록 · 사용 안 함 회색 — 놓이는 자리는 app-ui-spec 「상태 표기」의 「사용 여부」).
2. **색마다 뜻이 고정되어 있다.** 같은 색을 다른 뜻으로 쓰지 않는다.

   | 색   | 뜻                                        | 예                                           |
   | ---- | ----------------------------------------- | -------------------------------------------- |
   | 청록 | 긍정·완료·통과, 주 동작, 지금 선택한 것   | 통과, 완료, 사용, 주 버튼, 선택한 탭·메뉴    |
   | 호박 | 주의·대기·사람 확인이 필요함, 진행 중     | 확인 필요, 실행 중, 주의 안내                |
   | 적색 | 부정·실패·차단, 그리고 필수 입력 표시     | 실패, 실행 실패, 위험 동작, 라벨 뒤 「\*」   |
   | 회색 | 중립·결과 밖·끝난 것                      | 해당 없음, 미실행, 종료, 사용 안 함, 준비 중 |
   | 남색 | 본문 글자, 그리고 「걸려 있는 필터」 표시 | 선택된 필터 칩·숫자 타일의 테두리·채움       |

3. **안내는 기본이 무채색이다.** 색 있는 안내(호박)는 「주의해야 하는 것」에만 쓴다. 파란 안내 상자는 쓰지 않는다.
4. **숫자 타일·카드의 배경에는 색을 쓰지 않는다.** 상태색은 숫자·글자에만 입힌다. 예외는 상태 자체를 나타내는 면
   (통과·실패한 단계 카드, 결과 띠)뿐이다.
5. 상태를 짧게 보일 때는 **연한 배경 + 진한 글자의 알약(태그)** 을, 화면의 핵심 결과를 크게 보일 때는 **굵은 큰 글자에
   상태색**을 쓴다. 채운 적색 태그는 쓰지 않는다.

## 4. 강조와 선택

- **강조는 「지금 보고 있는 것」 하나에만** 붙인다. 실행할 수 있는지 같은 다른 사실은 강조가 아니라 버튼의 노출로 알린다.
- 선택 표시는 부품마다 정해져 있다 — 새로 만들지 않는다.

  | 부품                  | 선택된 모습                                                                         |
  | --------------------- | ----------------------------------------------------------------------------------- |
  | 메뉴                  | 연청록 바탕 + 청록 굵은 글자                                                        |
  | 탭                    | 청록 채움 + 흰 글자(알약). 보조 탭은 연청록 바탕 + 청록 테두리                      |
  | 필터 칩               | 남색 채움 + 흰 글자                                                                 |
  | 숫자 타일(필터)       | 남색 테두리(안쪽 1px 더) + 회색 바탕, 숫자는 남색                                   |
  | 단계 카드             | 청록 테두리 + 아래 3px 청록 띠 + 연청록 바탕                                        |
  | 표의 행               | 연청록 바탕 + 왼쪽 3px 청록 띠                                                      |
  | 선택한 대상의 상세 면 | 청록 테두리 + 머리줄 연청록 바탕                                                    |
  | 체크박스·라디오       | 브라우저 기본 모양에 청록 강조색 + 라벨. 라디오로 고른 행은 연청록 바탕 + 굵은 글자 |
  | 사용 중인 행          | 연청록 바탕 + 청록 태그(「현재」·「사용」). 고른 행과 달리 왼쪽 띠 없음             |

- **걸린 필터는 테두리로** 보인다(색 바탕보다 테두리).
- **쓸 수 없는 것은 숨기지 않고 흐리게** 한다(불투명도 0.4~0.5, 누를 수 없음). 왜 못 쓰는지는 툴팁이나 옆 문구로 알린다.
  「사용 안 함」으로 꺼 둔 카드도 같은 흐림이다.
  **예외 — 삭제처럼 되돌릴 수 없는 동작**은 흐리게 하지 않고 늘 누를 수 있게 둔다. 지금 할 수 없으면 누를 때 안내 모달로 이유와 대안
  (「사용 안 함」 등)을 보인다. 이유와 대안은 툴팁 한 줄에 담기 어렵고, 지우려는 순간에 보여야 하며, 키보드·터치에서도 닿아야 하기 때문이다.
  누르기 전 조건(먼저 해야 할 설정 등)이 있는 전환 동작도 같은 이유로 흐리게 하지 않고 누를 때 안내한다.
  **화면이 아직 없는 메뉴**도 흐리게 하지 않는다 — 「준비 중」 표시를 달고, 누르면 「준비 중」 화면이 그 사실을 알린다(결정 0003).
  **로그인 화면의 「로그인」**도 빈 칸이어도 흐리게 하지 않는다 — 브라우저가 채운 아이디 · 비밀번호는 첫 클릭 전에는 화면에 넘어오지 않아,
  흐리게 두면 두 번 눌러야 한다. 누르면 빈 칸 아래에 알린다.
- **다른 축·부분집합은 점선**으로 모양을 달리한다. 예: 합계에 들지 않는 칩, 아직 실행하지 않은 단계 카드.

## 5. 배치

- **페이지**: 제목(21px) + 설명 한 줄(12.5px 회색) 아래로 블록을 12~16px 간격으로 세로로 쌓는다.
- **블록**은 흰 카드(1px 선, 6px 라운드)다. 머리줄(제목 + 오른쪽 주석·버튼)과 본문으로 나눈다.
- **목록 화면의 순서**: (맥락 띠) → 요약 칩·숫자 타일 → 필터 줄(건수 맨 앞 → 셀렉트 → 검색 → 보기 도구 → 빈칸 → 동작 버튼.
  셀렉트는 단추로 여는 줄에 숨기지 않고 필터 줄에 펼친다 — 걸린 조건이 늘 보이게) → 표 → 페이지 나눔.
- **상세 화면의 순서**: 상단 줄(← 목록으로 · 경로 · 이전/다음) → 제목 → 요약 띠 → 단계·탭 → 본문.
- **동작 버튼은 머리줄 오른쪽**에 둔다(목록 도구의 동작은 필터 줄 오른쪽 끝, 카드마다의 추가는 카드 바닥). 한 영역에서 청록 주 버튼은
  하나뿐이다.
- **정렬**: 숫자는 오른쪽(자릿수 맞춤), 상태·배지·버튼 열은 가운데, 글은 왼쪽.
- **mono 글꼴은 ID·코드값에만** 쓴다(ID, 코드, 파일명, 버전). 한글 라벨에는 쓰지 않는다.
- **설명은 주석처럼** 붙인다. 카드 머리줄의 설명은 알약이 아니라 작은 회색 글자다.

## 6. 목업에 없는 화면을 만들 때

1. 이미 있는 화면 가운데 **가장 비슷한 구조**를 먼저 찾는다 — 목록형, 상세형, 설정형, 카드 격자형, 요약형, 등록형.
2. 부품은 [app-ui-spec 「컴포넌트」](app-ui-spec.md#5-컴포넌트)에서만 고른다. 맞는 부품이 없으면 화면에 새 모양을 짜 넣지
   말고 app-ui-spec 에 먼저 추가한다(새 공통 부품 — 다른 사람의 열린 PR 에 같은 용도가 있는지 확인하고 PR 본문에 「공통 부품 추가」를 적는다, collaboration.md 2절).
3. 새 상태가 생기면 위 3절의 색 뜻에 맞춰 정하고 [app-ui-spec 「상태 표기」](app-ui-spec.md#6-상태-표기--같은-뜻은-모든-화면에서-같은-색)에
   등재한 뒤 쓴다.
4. 색·글자 크기·간격은 app-ui-spec 의 단계 값에서만 고른다. 중간 값(13.2px, 다른 회색 등)을 만들지 않는다.
5. **색을 쓸지 망설여지면 무채로 둔다.** 색은 뜻이 있을 때만 쓴다.

## 7. 접근성

- 키보드 포커스는 모든 조작 요소에 **2px 청록 외곽선(바깥 2px 띄움)** 으로 보인다.
- 시스템의 「동작 줄이기」 설정을 켜면 전환 효과를 끈다.
- 글자 대비는 작은 글자 기준 4.5:1 이상이다. 초안에서 모자란 호박 글자와 사이드바 그룹 이름은 같은 색조로 진하게
  보정했다([app-ui-spec 「초안과 다른 곳·확인 필요」](app-ui-spec.md#8-초안과-다른-곳확인-필요) D8 · D9).
