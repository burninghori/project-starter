# app-ui 스타일 스펙

> 상태: 이 저장소 디자인 시스템의 기준 값이다(디자인 초안의 CSS 에서 뽑아 보정한 값 — 다른 곳은 8절).
> 화면이 「어떻게」 보이는지의 단일 출처다. 코드(`src/styles/app/`·`src/components/ui/`)가 이 값과 같다 — 값을 바꿀 때는
> 이 문서부터 고친다. 원칙은 [design-concept](design-concept.md), 틀과 치수는 [app-shell-spec](app-shell-spec.md).

## 1. 규칙

- 모양(색·라운드·그림자·글자)은 토큰 `var(--app-*)` 과 `app-*` 클래스로만. 배치는 Tailwind 유틸.
- **값은 이 문서의 표에 있는 것만 쓴다.** 표에 없는 중간 값을 만들지 않는다. 새 값이 필요하면 이 문서에 먼저 추가한다.
- 새 시각 패턴은 화면에 짜 넣지 않고 `src/styles/app/` 에 클래스로 선언한 뒤 [파일 지도](#7-파일-지도--어떤-클래스가-어디에-있나)에 등재한다.
- `npm run lint:styles` 가 색 리터럴·기본 팔레트·임의값·`styles/app` 밖 CSS 를 막는다.
- 목업 HTML 을 받아도 그 CSS·JS 를 그대로 복사하지 않는다. 이 문서의 값으로 app 클래스를 새로 쓴다.

## 3. 글자

본문은 13px · 줄 간격 1.5 · 글자 다듬기(antialiased)다. 크기는 아래 단계만 쓴다.

| 단계      | 크기 · 굵기 · 자간        | 쓰임                                                                               |
| --------- | ------------------------- | ---------------------------------------------------------------------------------- |
| 타일 숫자 | 22px · 700 · -0.6         | 숫자 타일 값(작은 타일은 20px)                                                     |
| 페이지    | 21px · 700 · -0.3         | 페이지 제목                                                                        |
| 결과 대   | 19px · 700 · -0.4         | 스텝 카드의 단계 상태, 맥락 띠의 최종 결과                                         |
| 결과      | 18px · 700 · -0.4         | 요약 띠 값, 단계 카드 결과, 결과 띠(초안 17px 은 18px 로 통합)                     |
| 모달      | 15px · 700                | 모달 제목, 브랜드 이름                                                             |
| 섹션      | 14px · 700                | 섹션 제목, 맥락 띠의 값, 단계 카드 이름                                            |
| 카드      | 13.5px · 700              | 카드 머리줄 제목                                                                   |
| 본문      | 13px · 400 (이름 600~700) | 본문, 표 내용, 메뉴(600), 스텝 이름(700)                                           |
| 본문 작게 | 12.5px · 600              | 버튼, 페이지 설명(400), 드롭존 제목                                                |
| 보조      | 12px · 500~600            | 안내 상자, 칩, mono 값                                                             |
| 라벨      | 11.5px · 400~700          | 표 머리(700), 입력 라벨(700), 주석·건수·경로(400), 작은 버튼(600) — 가장 많이 쓴다 |
| 메타      | 11px · 400~700            | 태그(700), 하단 정보, 카드 안 보조 줄                                              |
| 미세      | 10.5px · 400~700          | 부제, 단계 번호, 비율(%) 같은 곁 숫자                                              |
| 최소      | 10px · 600~700            | 사이드바 그룹 이름(자간 0.6), ID 버튼 안 태그                                      |

- 굵기는 400(본문)·500(안내)·600(버튼·라벨·메뉴)·700(제목·값·태그) 넷만 쓴다.
- 버튼·입력의 줄 간격은 브라우저 기본(normal)이다. 본문의 1.5 를 물려받으면 3~4px 높아진다(측정값).
- 숫자 열과 숫자 타일은 자릿수를 맞춘다(`font-variant-numeric: tabular-nums`).
- 작은 설명 문단은 줄 간격 1.35~1.45 로 조금 좁힌다.

## 5. 컴포넌트

「범위」의 **공통**은 `core.css`·`components/` 에 있고, **화면 전용**은 그 화면을 만들 때 `modules.css` 에 둔다.

| 아코디언    | 펼친 줄 패널 — 줄을 누르면 바로 아래 칸 전체에 붙는 안쪽 패널. 회색 바탕 행 안의 흰 상자 — 왼쪽 3px 청록 띠 · `line` 테두리 · 6px 라운드 · 그림자 `shadow-sm` · 왼쪽 44px 들여쓰기. 머리(제목 12.5/600 + 회색 건수 + 오른쪽 끝 단추 · 안내) 아래 본문(표 하나, 또는 안내 한 줄). 있을 때만 오른쪽 상자(250px, 「이름 · 값」 줄 — 있으면 `app-acc--side`). 펼친 줄은 조건이 바뀌면 비우고, 「모두 펼치기 / 모두 접기」는 이 쪽의 줄만                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 줄 펼침    | 공통 |

### 떠 있는 면

모달·토스트의 치수는 [app-shell-spec 「떠 있는 면」](app-shell-spec.md#6-떠-있는-면). 모달 폭은 기본 720px, 표가 많으면 넓은 980px.
팝오버 메뉴는 위 「조작」 표와 4절 「부품 치수」에 있다 — 떠 있는 면이지만 `overlay-store` 를 거치지 않고 트리거 옆에 뜬다.

### 화면 전용 (그 화면을 만들 때 `modules.css`)

아직 없다. 한 화면만 쓰는 부품은 그 화면을 만들 때 `modules.css` 에 두고 이 절에 표(부품 · 생김새 요지 · 화면)로 등재한다.
두 번째 화면이 같은 모양을 쓰면 「공통」으로 올린다.

## 6. 상태 표기 — 같은 뜻은 모든 화면에서 같은 색

짧게 보일 때는 **태그**, 크게 보일 때는 **굵은 글자에 같은 색**이다. 값이 없으면 색 없이 회색 「-」.
색의 뜻은 [design-concept 3절](design-concept.md#3-색을-쓰는-규칙)이 정한다. 새 상태는 그 뜻에 맞춰 색을 정하고 이 표에 등재한 뒤 쓴다.
라벨은 그 도메인의 `src/api/<domain>/` 에 `Record<Enum, string>` 으로 한 곳에 두고, 색은 이 표를 따른다.

| 상태           | 청록                    | 호박    | 적색      | 회색                                                                             |
| -------------- | ----------------------- | ------- | --------- | -------------------------------------------------------------------------------- |
| 실행 상태(예)  | 완료                    | 실행 중 | 실행 실패 | 미실행                                                                           |
| 검사 결과(예)  | 통과                    |         | 실패      | 대기 · 검사 중(글자)                                                             |
| 사용 여부      | 사용(상태 열이 있는 표) |         |           | 사용 안 함. 상태 열 없이 이름 옆에 붙는 곳은 사용 안 함만 태그, 사용은 표시 없음 |
| 메뉴 공개 상태 |                         |         |           | 준비 중. 열린 메뉴는 표시 없음(8절 D49)                                          |

- 결과 축 밖의 시스템 상태(예: 「미수행」 — 앞 단계가 막혀 하지 않음)는 회색 + 점선 테두리 태그(`Tag` 의 `system`)다.
- 스텝 카드처럼 상태를 큰 글자로 보일 때도 같은 색을 쓴다: 통과 청록, 실패 적, 진행 중 호박, 대기 · 미실행 회색.

## 9. 글꼴 — 사용자가 설치하지 않아도 같은 모양

초안의 `font-family` 첫 자리는 Pretendard 인데 글꼴 파일을 불러오지 않았다. 그래서 Pretendard 가 깔린 PC 에서만 의도한 모양이
나오고, 나머지는 운영체제 글꼴(맥 Apple SD 산돌고딕 Neo · 윈도 맑은 고딕)로 보인다 — 줄 길이·굵기가 달라 표 폭이 바뀐다.

| 방식                                                                     | 사용자 설치 | 장점                                                                  | 단점                                                                                            |
| ------------------------------------------------------------------------ | ----------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **A. 앱이 글꼴 파일을 함께 배포**(npm `pretendard` 패키지, OFL 라이선스) | 없음        | 모든 PC 에서 같은 모양. 외부망이 막혀도 동작(우리 서버가 파일을 준다) | 글꼴 파일만큼 배포물이 커진다. 화면에 쓰인 글자 조각만 내려받는 방식을 쓰면 첫 로딩 부담이 작다 |
| B. 외부 CDN 에서 불러오기                                                | 없음        | 설정 한 줄                                                            | 사내 · 폐쇄망에서 외부 CDN 이 막히면 시스템 글꼴로 돌아간다. 외부 요청이 생긴다                 |
| C. 운영체제 글꼴만                                                       | 없음        | 아무것도 안 해도 된다                                                 | 맥·윈도 모양이 다르다                                                                           |

- **A 로 정했다.** 사용자 설치 없이 같은 모양이 나오는 유일한 방식이고, 폐쇄망에서도 깨지지 않는다.
- 반영되어 있다 — npm `pretendard` 의존성, `app.css` 의 글꼴 CSS import, `--app-font` 첫 자리.
