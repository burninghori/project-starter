# 명세 — DB 스키마 · API

기능을 나눠 개발하기 전에 **여러 개발자가 같이 기대는 계약**을 먼저 정의해 두는 곳이다.

| 문서 | 내용 | 코드에서의 정본 |
|---|---|---|
| [db-schema.md](db-schema.md) | 테이블·컬럼·제약·관계·상태 코드 | `backend/app/domains/*/models.py` + `backend/migrations/versions/` |
| [api.md](api.md) | 엔드포인트·요청·응답·오류 code | `backend/app/domains/*/router.py`·`schemas.py` → 자동 생성 문서 `/api/docs` |

## 규칙

1. **명세 먼저, 코드 다음.** 새 테이블·API 는 이 문서에 먼저 적고 그다음 구현한다. 특히 공통 테이블(두 기능 이상이 쓰는 테이블)은
   명세가 확정되기 전에 구현하지 않는다.
2. **구현되면 코드가 정본이다.** 구현 중 명세와 달라지면 같은 변경에서 명세를 고친다. 명세와 코드가 다르면 버그다.
3. API 의 실제 요청·응답 형식은 backend 를 띄워 `/api/docs`(OpenAPI)에서 확인할 수 있다. 이 문서는 **설계 의도와 업무 규칙**
   (언제 409 인지, 어떤 상태에서 무엇을 막는지)을 담는다 — 자동 문서가 말해 주지 않는 부분이다.
4. 상태 생애주기는 표로 적는다: 상태, 들어오는 전이, 나가는 전이, 누가 바꾸나.
