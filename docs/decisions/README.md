# 설계 결정 기록

코드만 봐서는 알 수 없는 **왜**를 남긴다. 여러 개발자와 각자의 AI 가 같은 결정을 다시 논의하지 않게 하는 것이 목적이다.

## 언제 쓰나

- CLAUDE.md 「도메인 원칙」·「프로젝트 기조」를 바꾸거나 새로 정할 때
- 공통 테이블(두 기능 이상이 쓰는 테이블)의 구조를 확정하거나 바꿀 때
- 기술 선택(라이브러리·구조)을 바꿀 때
- 기획 초안과 다르게 설계할 때

화면 하나의 필드 배치처럼 한 기능 안에서 끝나는 결정은 PR 본문으로 충분하다.

## 형식

파일 이름은 `NNNN-<제목>.md`(4자리 순번). **결정 자체가 바뀌지 않는 보강**(세부 방식·명칭·예시·영향 목록 추가)은 머지된
기록이라도 그 파일을 직접 고친다 — 수정 시점은 git 이력이 담는다. **결정을 뒤집거나 결정 문장이 바뀌면** 새 기록을 쓰고
옛 기록의 상태를 「대체됨(NNNN)」으로만 바꾼다. 결정 일부만 바뀌면 「확정 · 일부 대체됨(NNNN — 바뀐 부분)」으로 두고, 옛 기록의
그 문장 끝에 대체 표시를 단다.

```markdown
# NNNN. 제목

YYYY-MM-DD · 상태: 확정 | 대체됨(NNNN) | 확정 · 일부 대체됨(NNNN — 바뀐 부분)

## 배경
무엇이 문제였나

## 결정
무엇을 하기로 했나

## 근거
왜 그것인가. 검토한 대안과 버린 이유

## 영향
무엇이 달라지나(코드·문서·외부 협의)
```
